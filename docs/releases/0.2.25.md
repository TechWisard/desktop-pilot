Desktop Pilot 0.2.25 открывает уже сохранённый профиль, даже если фоновая операция записи SQLite ещё не завершилась.

## Что исправлено

Раньше каждый запуск окна настроек повторно захватывал эксклюзивное право записи в SQLite ради создания уже существующих таблиц. При одновременном сохранении статистики или большого каталога это могло задержать открытие настроек до тайм-аута и вернуть ошибку «database is locked».

Теперь полный, проверенный профиль открывается для чтения без повторного захвата права записи. Новые и восстановленные пустые профили по-прежнему проходят защищённое транзакционное создание таблиц. Проверка чужой или повреждённой базы остаётся обязательной; при замене файла между проверкой и открытием программа не создаёт таблицы автоматически.

Регрессия воспроизводит открытие настоящего профиля во время незавершённой записи другого SQLite-соединения: исходное поведение завершается ошибкой, исправленное читает только подтверждённые данные. Сохраняются ручные правила, история, оригинальные ярлыки, размещение и отмена.

Никаких новых служб, настроек, зависимостей и телеметрии. Скачайте **DesktopPilot-0.2.25-windows-x64.zip** и проверьте архив по **SHA256SUMS.txt**. Файл программы не подписан цифровой подписью.

## English

Desktop Pilot 0.2.25 reopens a verified existing SQLite profile without acquiring a redundant writer lock. Settings can read committed catalog and configuration data while a background writer holds its own transaction. The old startup path could instead wait for the busy timeout and fail. New/empty profiles retain atomic writer-protected schema creation, and foreign/corrupt files remain protected.

The regression uses actual SQLite connections and the production Store::open path; it is not a human startup-latency benchmark. Manual choices, original shortcuts, usage history, positions and Undo remain intact. No added accounts, settings, services, dependencies or telemetry. The unsigned Windows x64 archive is accompanied by SHA256SUMS.txt.
