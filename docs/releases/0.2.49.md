Desktop Pilot 0.2.49 делает ручное управление предсказуемым, если одно окно программы выключено, а другое одновременно пытается возобновить фоновую работу.

## Что исправлено

Ранее ручная команда в отключённом профиле сначала проверяла режим под блокировкой запуска, затем освобождала блокировку и только после этого изменяла правило или выполняла «Применить»/«Отменить». Другое окно могло включить фоновый процесс в этом промежутке. Два пути управления могли действовать одновременно, вопреки явно выбранному режиму.

Теперь команда, проверка отключённого режима и её выполнение защищены одним механизмом согласования с запуском и отключением. Ручная работа по-прежнему не запускает фоновый процесс, не требует исправного установленного EXE и использует существующую защиту файлов, историю, правила и Undo. Включённый режим продолжает отправлять команды через очередь.

Новых параметров, служб, зависимостей и телеметрии нет. Для проверки используется воспроизводимый Windows-сценарий с настоящей асинхронной командой Settings, именованной блокировкой профиля и SQLite. Тест не означает, что измерена экономия времени людей.

Скачайте `DesktopPilot-0.2.49-windows-x64.zip`; контрольные суммы — `SHA256SUMS.txt`. Программа Windows x64 не имеет цифровой подписи.

## English

Desktop Pilot 0.2.49 serializes explicit local manual actions in a disabled profile with a concurrent Start or Turn off from another Settings window. Previously Settings released the startup mutex after deciding that the profile was disabled, before executing the manual action. A second window could start background work in that gap.

The command now retains the same startup mutex through mode verification and direct execution. Disabled profiles still work offline without installing or launching the background worker; enabled profiles continue to queue commands. Original shortcuts, rules, history, desktop positions and Undo remain protected. No new configuration, services, dependencies or telemetry. Windows x64 executable is unsigned.
