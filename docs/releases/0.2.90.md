# Desktop Pilot 0.2.90 — приоритет ручного выбора и быстрый просмотр истории

## Что изменилось

**Ручное «Всегда» не вытесняет работающий ярлык вместо временно недоступного.** При двух занятых местах ранее отсутствующий автоматический ярлык мог оставаться защищённым на время восстановления источника, даже когда пользователь явно добавлял третье приложение через «Всегда». В результате программа удаляла рабочий быстрый ярлык, оставляя недоступный. Теперь явный выбор освобождает прежде всего место временно недоступного автоматического приложения. Настоящие ручные закрепления и ручные позиции по-прежнему защищены; без нового выбора обычная отсрочка при пропаже источника сохраняется.

**Холодный предварительный просмотр не загружает историю из далёкого будущего.** Если часы Windows ранее были ошибочно переведены вперёд и сохранили множество событий, программа не читает эти заведомо неприменимые строки из SQLite на каждом открытии каталога. Данные остаются в базе и могут вновь учитываться, когда время станет подходящим. Обычные события и небольшие коррекции времени сохраняют прежнее поведение.

История использования, оригинальные файлы, правила «Всегда» и «Никогда», настройка автоматического режима, возможность отката и локальное хранение остаются без изменений. Новых служб, сетевых зависимостей, прав или скрытой телеметрии нет.

## Проверка

Для конфликта выбора создана регрессия на реальном алгоритме отбора и независимая последовательность на штатной базе SQLite, чтении Windows `.url`, сохранении правила, `engine::preview`, отмене выбора и проверке исходных байтов. Синтетический пример с двумя местами показывает **одну ненужную замену работающего ярлыка до исправления и ноль после**. Ручная позиция отсутствующего ярлыка сохраняет приоритет.

Проверка загрузки истории использует ту же штатную выборку SQLite, которую применяет просмотр, и **512** искусственных записей из далёкого будущего. До ограничения просмотр получал **514** строк, после — **2**; все **514** остались в базе. Эти числа относятся к тестовым данным, а не ко времени работы реального пользователя.

Форматирование, Rust-тесты, строгий Clippy, сборка, нативные Windows-проверки и проверки публикации выполняются штатным CI на Windows Server 2022 и 2025, без отключения защитных этапов. Подробнее: [конфликт явного выбора](../research/2026-11-02-explicit-always-offline-auto-capacity.md) и [история после исправления часов](../research/2026-11-02-future-history-preview-bound.md).

Физическая проверка Windows 11, отключаемых дисков, интерфейса при масштабировании 100–200% и реальные измерения времени до результата ещё необходимы.

## Установка

Распакуйте **DesktopPilot-0.2.90-windows-x64.zip**. Контрольные суммы содержатся в **SHA256SUMS.txt**. Исходники — **DesktopPilot-0.2.90-source.zip**. Исполняемый файл не подписан цифровой подписью.

## English

Desktop Pilot 0.2.90 keeps a working automatic shortcut when a user explicitly chooses a new **Always** shortcut and another managed automatic shortcut is temporarily offline. Hard manual placements remain protected; ordinary offline grace is unchanged unless capacity is actually exceeded. Cold catalog previews no longer load distant-future usage rows left by a corrected Windows clock, without deleting that history.

Native Windows URL, SQLite, actual preview and selection regressions cover the conflicting choices and unchanged original files. The historical-row test checks 514 synthetic saved rows versus two rows needed for preview. These are correctness and read-count checks, not human-time savings. The established Windows Server 2022/2025 CI remains required, and interactive Windows 11 acceptance remains open. The executable is unsigned.
