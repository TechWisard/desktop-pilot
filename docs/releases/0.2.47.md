Desktop Pilot 0.2.47 устраняет редкий конфликт между ручной командой и отключением фоновой работы.

## Что изменилось

Если одна копия настроек отправляет команду «Применить», «Отменить» или меняет правило, а другая одновременно отключает Desktop Pilot, программа больше не может записать новую ожидающую команду после завершённой остановки фонового процесса. Проверка готовности и запись команды теперь согласованы одним механизмом блокировки. Отключение отменяет команды, поставленные в очередь раньше, и не оставляет зависших задач.

Ручное управление ранее отключённым профилем по-прежнему работает без запуска слежения. Исходные ярлыки, позиции, правила, история, локальные данные и безопасный откат сохранены. Новых настроек, зависимостей, телеметрии или сетевых служб нет.

Контрольный сценарий использует настоящие SQLite, Windows mutex и путь обработки команд приложения. Длительность пользовательских действий на физической Windows 11 пока не измерялась. Windows x64 EXE не подписан цифровой подписью.

Скачайте `DesktopPilot-0.2.47-windows-x64.zip`; контрольные суммы доступны в `SHA256SUMS.txt`.

## English

Desktop Pilot 0.2.47 prevents a manual Settings action from being queued **after** another Settings instance has disabled background tracking. Worker readiness and command insertion are serialized by the same startup lock, so an explicit Turn off cancels already queued work without leaving later orphaned pending requests. Local manual actions while disabled still work without restarting tracking.

Original shortcuts, desktop positions, user rules, usage history and Undo are preserved. The regression exercises the actual Windows startup/background mutex, Settings queue and SQLite. No additional settings, dependencies, services or telemetry; the Windows x64 executable is unsigned.
