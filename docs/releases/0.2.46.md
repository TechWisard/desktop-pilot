Desktop Pilot 0.2.46 устраняет рассогласование идентификаторов ярлыков при разных написаниях расширенного сетевого пути Windows (UNC).

## Исправлено

Сетевой путь вида `\\Server\Share\...` и его расширенная форма `\\?\UNC\Server\Share\...` должны определять один и тот же исходный объект. Раньше вариант с `unc` в нижнем или смешанном регистре мог ошибочно получить другой идентификатор приложения. Это создавало риск повторного появления одного сетевого ярлыка или неправильного сопоставления после изменения представления пути.

Теперь префикс распознаётся без зависимости от регистра. Остальная часть пути, аргументы запуска, ручные правила, история, позиции, исходные файлы и безопасная отмена не меняются. Различающиеся URL и разные локальные/сетевые цели по-прежнему остаются различными.

Добавлена регрессионная проверка реальной логики присвоения идентификаторов, сохранены штатные тесты Windows и проверки публикации. Реальное подключение и отключение SMB-ресурса ещё не проверялось. Новых настроек, зависимостей, телеметрии или фоновых служб нет.

Скачайте `DesktopPilot-0.2.46-windows-x64.zip`; контрольные суммы указаны в `SHA256SUMS.txt`. Исполняемый файл не подписан цифровой подписью.

## English

Desktop Pilot 0.2.46 normalizes the case-insensitive extended UNC namespace prefix consistently with ordinary Windows network paths. Different lettercase in the `UNC` component no longer changes a saved shortcut's launch identity or catalog ID. It retains distinct drive paths, case-sensitive URL payloads, launch parameters, manual choices, history, original files and file-safe Undo.

Production identity regressions and existing Windows integration/release checks protect the change. Live SMB disconnection/recovery and physical Windows 11 input latency remain unmeasured. No added settings, dependencies, telemetry or services. The Windows x64 executable is unsigned.
