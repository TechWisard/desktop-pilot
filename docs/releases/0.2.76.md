Desktop Pilot 0.2.76 — остановка наблюдения предотвращает запоздалую запись активности.

## Что улучшено

После сохранения переключателя наблюдения в положение «Выключено» Desktop Pilot больше не записывает в историю активности и прогресс обучения устаревшие события, которые фоновый процесс успел подготовить до остановки. Раньше между чтением настроек и записью в SQLite существовало короткое окно, в котором запоздалое событие могло сохраниться уже после подтверждённой остановки.

Теперь разрешение проверяется **непосредственно внутри транзакции записи**: и для учёта активности, и для обучения. Операция «Выключить» также блокирует эти запоздалые записи. При явном возобновлении наблюдения новая достоверная активность продолжает учитываться. Настройки, ручные закрепления, исходные ярлыки, история предыдущих сеансов и возможность отмены размещений сохраняются.

Это исправление касается согласованности пользовательского управления с локально сохраняемой активностью. Оно не добавляет настройки, скрытый сбор данных, сетевые обращения, фоновую службу или новые зависимости.

## Проверки и ограничения

Регрессионный тест `engine::tests::paused_collection_rejects_in_flight_usage_and_learning_writes` моделирует последовательность «наблюдение активно → событие подготовлено → остановка сохранена другим подключением → попытка записи → отключение фоновой работы → возобновление». Используются настоящие SQLite/WAL, штатные операции учёта и обучения и безопасный тестовый ярлык. Проверяется, что при остановке количество запоздалых записей равно нулю, сохранённые счётчики и исходный файл не изменяются, а новая активность после возобновления учитывается.

[Изменения и проверка PR №96](https://github.com/TechWisard/desktop-pilot/pull/96) · [Исследование и воспроизведение](../research/2026-10-31-paused-observation-write-boundary.md). Сохранены обычные проверки Rust, форматирования, Clippy без предупреждений, сборки, нативных сценариев и публикации на Windows Server 2022/2025. Полная итоговая проверка версии и собранного EXE выполняется отдельным выпускным заданием.

Тест моделирует гонку с контролируемым порядком событий и не измеряет вероятность такого случая или экономию времени настоящих пользователей. Отдельно остаются физическая Windows 11 при масштабе 200%, реальные отключения сетевых источников, длительная смена проектов и измерение времени до первой пользы.

Для Windows x64 распакуйте **DesktopPilot-0.2.76-windows-x64.zip**, запустите `desktop-pilot.exe`, проверьте SHA-256 по **SHA256SUMS.txt**. Исполняемый файл не подписан цифровой подписью.

## English

Desktop Pilot 0.2.76 prevents queued foreground activity and learning increments from being persisted **after** the user has saved a pause or Turn off. The previous polling-time permission snapshot was not sufficient when a sampled event crossed a Settings commit. Both writers now recheck the saved permission inside the real SQLite writer transaction. Explicit resumption accepts fresh genuine activity; existing history, manual shortcut rules, original files and Undo are preserved.

A native shortcut and SQLite/WAL production-path regression covers active observation, a separately committed pause, rejected stale updates, Turn off, and safe resumption without changing source bytes. The unchanged Windows Server 2022/2025 test, formatting, strict Clippy, build, native and publication checks gate the release; the release executable is independently validated before publishing. The fixture proves the tested scheduling interleaving, **not** real-world time savings or physical Windows 11 device behavior. The executable is unsigned.
