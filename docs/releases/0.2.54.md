Desktop Pilot 0.2.54 — разрешение пользователя на наблюдение имеет приоритет над устаревшим состоянием фонового процесса.

## Что исправлено

Если пользователь отключал наблюдение или выполнял «Отключить» во время очередного опроса, фоновый процесс мог ещё использовать полученную ранее настройку и считать уже установленные системные обработчики ввода разрешёнными до следующего цикла. Теперь перед каждым использованием установленных обработчиков проверяются актуальные настройки, отключение и завершение работы. При отзыве разрешения обработка ввода выключается перед удалением системных обработчиков, а наблюдение в текущем цикле не выполняется.

Ручные ярлыки, настройки, история, восстановление и Undo сохраняются. Никаких новых фоновых служб, разрешений, хранилищ, зависимостей или телеметрии нет.

Проверки воспроизводят изменение настроек на другом соединении SQLite между чтением старого состояния и использованием уже существующих обработчиков; отдельно проверяют паузу, явное отключение, завершение, возобновление и сохранность пользовательских данных. Проверки на серверах Windows не заменяют измерение реального энергопотребления или испытания на физическом компьютере Windows 11.

## English

Desktop Pilot 0.2.54 rechecks persisted tracking consent on every existing Windows input-hook poll, not only when hooks are first installed. A pause, Turn off or shutdown that overtakes a previously read monitor snapshot now disables evidence and releases already-installed hooks; foreground collection is gated on successful current authorization. Manual shortcuts, preferences, history, recovery and Undo remain intact. No new services, storage, dependencies, settings or telemetry. The Windows x64 executable is unsigned.
