Desktop Pilot 0.2.83 — сохранение ручных правил при прерывании фоновой работы.

## Что исправлено

Если фоновой процесс завершался после сохранения в очередь, но до выполнения ручного правила «Всегда» или «Никогда», следующий запуск мог отметить такое правило ошибкой. Пользователю приходилось выбирать его снова, хотя изменение ещё не начиналось.

Теперь незапущенные ручные правила остаются в очереди после перезапуска фонового процесса и выполняются в исходном порядке. Это важно, например, при последовательной смене «Никогда» на «Всегда»: последняя воля пользователя сохраняется.

Ранее начавшиеся команды и ещё не начатые операции «Применить», «Отменить» и обновления каталога **не повторяются автоматически** после сбоя, чтобы не рисковать частично изменёнными файлами. Явная команда очистки прерванных операций и отключение фоновой работы по-прежнему отменяют очередь. Применение ручного правила само по себе не переставляет значки: пользователь управляет размещением отдельно.

Исходные ярлыки, пользовательские настройки, история наблюдений, ручное размещение и откат не изменены. Новые службы, настройки, интернет-запросы и телеметрия не добавлены.

## Проверки

Регрессионный тест воспроизводит смешанную очередь: начавшаяся команда, два незапущенных ручных правила, а между ними — команды размещения и отмены. Применяются только ручные правила, в порядке Never → Always; ни одна файловая операция не воспроизводится повторно. Тест использует настоящую SQLite, штатный разбор .url, очередь и обработчик команд; остановка фонового процесса моделируется. Проверены исходные байты ярлыка, отсутствие побочных перемещений и повторных событий.

В существующем полном Windows CI на каждой из платформ Windows Server 2022 и 2025 прошли 371 тест Rust, 29 нативных интеграционных проверок, 9 проверок публикации, cargo fmt, строгий Clippy и сборка. [Ветка изменений](https://github.com/TechWisard/desktop-pilot/actions/runs/41348337500), [проверка объединённого main](https://github.com/TechWisard/desktop-pilot/actions/runs/41348885774), [PR #120](https://github.com/TechWisard/desktop-pilot/pull/120), [исследование и сценарий](https://github.com/TechWisard/desktop-pilot/blob/main/docs/research/2026-11-01-pending-manual-policy-recovery.md).

Реальная авария фонового процесса на физическом Windows 11, рабочий стол Explorer при масштабировании 200%, длительные отключения внешних источников и экономия времени реальных пользователей не проверялись.

Для Windows x64 распакуйте **DesktopPilot-0.2.83-windows-x64.zip** и запустите `desktop-pilot.exe`. Сверьте SHA-256 архива по **SHA256SUMS.txt**. Исполняемый файл не подписан цифровой подписью.

## English

Desktop Pilot 0.2.83 preserves queued, unclaimed Always/Never shortcut choices across a background-worker restart. Saved user decisions are processed in their original order. In-progress actions and pending filesystem-changing Apply/Undo/rescan operations are still cancelled rather than replayed after an interruption. Explicit recovery and Turn off continue to cancel the queue. No new service, telemetry, network access or settings are introduced.

The native regression uses the production SQLite queue, Windows shortcut parser and command dispatcher with a synthetic interruption; it checks original file bytes, execution order and lack of unintended layout changes. Rust, strict Clippy, packaging guards, build and native integration tests passed on Windows Server 2022 and 2025. Physical Windows 11 Explorer recovery, high-DPI UI behavior and measured productivity remain outside this automated verification. The Windows executable is unsigned.
