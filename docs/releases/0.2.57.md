Desktop Pilot 0.2.57 — ручные действия остаются доступными при временном отказе Windows во включении отслеживания ввода.

## Что изменилось

Если Windows временно не позволяет зарегистрировать обработчики событий клавиатуры или мыши, Desktop Pilot больше не завершает весь фоновый процесс из-за этой ошибки. Учёт активности приостанавливается с понятным предупреждением, а управление ярлыками и отмена изменений остаются доступными. Программа повторяет попытку не чаще одного раза в 30 секунд, без постоянной нагрузки и повторяющихся уведомлений.

После восстановления доступности отслеживания программа возобновляет его, не создавая фиктивных событий использования. Ручной режим, явное отключение, существующие правила, история, файлы и Undo сохраняются. Ошибки самой базы данных по-прежнему отображаются, а не скрываются под предупреждением о вводе.

Регрессионные испытания используют реальный путь управления обработчиками, SQLite, создание/отмену ярлыка и инъекцию ошибки регистрации. Физическое изменение политики Windows не воспроизводилось. Новых настроек, сервисов, зависимостей и телеметрии нет. Windows x64 EXE не подписан цифровой подписью. Контрольные суммы в SHA256SUMS.txt.

## English

Desktop Pilot 0.2.57 keeps the tray and manual shortcut actions usable when Windows temporarily refuses keyboard/mouse input-hook registration. Observation is paused with an actionable warning, and registration is retried no more than once every 30 seconds. Successful recovery does not invent usage data. Manual mode and explicit Turn off still release input hooks immediately.

Regressions exercise the production hook lifecycle, genuine SQLite/shortcut Apply and Undo, failure/retry, safe recovery, and the distinction between OS hook refusal and database corruption. No extra service, configuration, dependency, or telemetry. Windows x64 executable is unsigned.
