# Desktop Pilot 0.2.105 — точный учёт работы на границе суток

## Исправлено

**Ночная работа теперь относится к тому дню, когда она действительно наблюдалась.** Если пользователь продолжает работать в приложении около полуночи, а запись SQLite задерживается из-за временной блокировки базы данных, прежняя логика могла записать весь отрезок работы в новые сутки. Это искажало число активных дней и могло повлиять на обоснованность последующих рекомендаций.

Дата для дневной статистики и отметка последней активности теперь берутся из **одного подтверждённого наблюдения**, даже если запись ожидает освобождения базы. Повторные попытки записи не меняют исходную дату. Исторические записи не переписываются; пороги, пользовательские запреты, ручное расположение, оригинальные ярлыки и локальный режим работы остаются без изменений.

## Проверка и ограничения

[Воспроизведение, исходная причина и тесты](../research/2026-11-03-usage-observed-calendar-day.md). Регрессионный тест использует настоящие обработчики активности и SQLite: два наблюдения по 12 секунд по обе стороны местной полуночи должны сохраняться в разных календарных днях с правильными отметками сеанса. До исправления тест выявил объединение этих 24 секунд в один день. Проверки продолжительных сеансов, коротких обращений, приостановки учёта и блокировок SQLite сохранены.

Штатная сборка проверяется на Windows Server 2022 и 2025: форматирование, тесты Rust, строгий Clippy, сборка, нативные интеграционные сценарии и проверки публикации. Это воспроизводимый технический результат, а не подтверждённая экономия времени пользователей. Физические испытания Windows 11, реального долгого удержания блокировки SQLite и изменения часового пояса остаются отдельными задачами.

## Установка

Скачайте **DesktopPilot-0.2.105-windows-x64.zip**, распакуйте и запустите программу. Сверьте контрольную сумму с **SHA256SUMS.txt**. Исходники предоставлены в **DesktopPilot-0.2.105-source.zip**. Исполняемый файл не подписан цифровой подписью.

## English

Desktop Pilot 0.2.105 assigns foreground activity to the **calendar day when it was observed**, not the day when a delayed SQLite write finally completes. A single confirmed local timestamp now determines both the daily usage bucket and the last-session checkpoint; database write retries preserve that timestamp. Existing history, manual policies, shortcut placement, original files, local-only operation and Undo are unchanged.

The native SQLite regression reproduces two twelve-second samples across local midnight and checks separate daily aggregates and the final session checkpoint. The old implementation failed that assertion. Windows CI checks formatting, Rust tests, strict Clippy, the build, native integration and release safeguards on Windows Server 2022 and 2025. Real-world time savings, interactive Windows 11 behavior and actual prolonged database contention have not been measured.
