Desktop Pilot 0.2.80 — редкие приложения и ручные правила больше не смешиваются из-за путей к разным томам Windows.

## Что улучшено

**Отдельные ярлыки сохраняют собственную историю и настройки.** В определённых старых и нестандартных профилях путь к приложению через постоянный идентификатор тома Windows (Volume GUID) или пространство устройств GLOBALROOT мог ошибочно совпасть с относительным путём другой программы. Из-за этого две разные программы получали один идентификатор в каталоге, а запись второй могла заменить первую вместе с выбранным пользователем правилом **«Всегда»** или **«Никогда»**.

Теперь при определении личности ярлыка Desktop Pilot сохраняет принадлежность к пространству устройств. Обычные эквивалентные записи одного файла через диск (например, C:\) и его длинный вариант, а также варианты UNC, по-прежнему сопоставляются как один источник. Не добавлены новые настройки, фоновое сканирование сети, телеметрия, зависимости или перестановки рабочего стола.

**Что не изменяется:** исходные ярлыки и другие файлы пользователя, существующие сохранённые правила, история, расположение управляемых копий и возможность отмены. Ранее полностью перезаписанные записи другого приложения автоматически восстановить невозможно.

## Проверки

Два новых теста используют настоящие идентификаторы приложений и SQLite-каталог. До исправления на Windows Server 2022 и 2025 тесты воспроизвели схлопывание двух разных приложений в одну запись: [контрольный прогон](https://github.com/TechWisard/desktop-pilot/actions/runs/41275522698) — 353 прежних теста прошли, два новых не прошли. После исправления [проверка исходной ветки](https://github.com/TechWisard/desktop-pilot/actions/runs/41275973835) завершилась успешно на обеих Windows-системах: 355 тестов Rust на каждой, штатные нативные проверки, защитные проверки выпуска, форматирование, строгий Clippy и сборка.

[Исследование, точные сценарии и ограничения](https://github.com/TechWisard/desktop-pilot/blob/main/docs/research/2026-11-01-device-namespace-identities.md).

Это проверка логики приложения и SQLite с искусственными путями, **не** измерение экономии времени людей. Физически подключённый/отключённый том Volume GUID, интерактивный Windows 11 и масштаб интерфейса 200% не проверялись. Новая версия не содержит незавершённую функцию организации рабочего стола из черновых PR.

Для Windows x64 распакуйте **DesktopPilot-0.2.80-windows-x64.zip**, запустите `desktop-pilot.exe` и сверьте SHA-256 по **SHA256SUMS.txt**. Исполняемый файл не имеет цифровой подписи.

## English

Desktop Pilot 0.2.80 preserves distinct app identities for Windows Volume GUID and GLOBALROOT namespace targets. Previously those absolute device paths could collapse into unrelated relative launch profiles, silently replacing a catalog entry and its Always/Never rule. Conventional extended drive-letter and UNC aliases continue to share their expected identity. Original shortcut files, existing history, manual placement and Undo are not rewritten; previously overwritten records cannot be reconstructed automatically. No telemetry or extra background activity.

Two real SQLite/catalog regressions failed before the correction on both Windows Server 2022 and 2025, while 353 existing Rust tests passed. Corrected source checks passed 355 Rust tests, native fixtures, publication safeguards, strict Clippy, formatting and build on each runner. Physical Windows 11 interaction, mounted/removable volume behavior and end-user time savings remain unverified. The Windows executable is unsigned.
