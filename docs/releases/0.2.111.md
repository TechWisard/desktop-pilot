# Desktop Pilot 0.2.111 — чистое прерывание размещения ярлыков

## Что улучшено

При обновлении быстрых ярлыков источник мог стать недоступным или измениться уже после обновления списка приложений. Если подготовка нового размещения прерывалась до записи операции в историю, Desktop Pilot оставлял временную папку с резервными копиями. Несколько таких попыток могли постепенно занимать место на диске, хотя размещение не изменилось.

Теперь неуспешная подготовка удаляет только свою новую временную папку. Уже подтверждённые операции, их резервные копии и возможность «Отменить последнее изменение» сохраняются. Существующие ярлыки и исходные файлы не перезаписываются; никаких новых разрешений, служб, настроек или сетевого обмена не требуется.

## Как проверено

Регрессионный сценарий использует настоящий механизм применения Desktop Pilot, SQLite и ярлыки Windows `.url`: сначала размещает знакомый ярлык, затем требует заменить его, изменяет исходник новой программы между проверкой каталога и копированием и проверяет неуспешную подготовку. Подтверждаются отсутствие лишних папок и временных значков, сохранность существующей копии и её идентификатора, отсутствие фиктивной транзакции, успешный повтор и последующий откат.

[Исследование, воспроизводимый сценарий и ограничения](../research/2026-11-04-unjournaled-shortcut-preparation.md). Пройденные проверки на Windows Server 2022 и 2025 охватывают Rust, форматирование, строгий Clippy, сборку и нативные интеграционные проверки. Испытания на реальном рабочем столе Windows 11, масштабирование интерфейса 100–200% и длительные прерывания облачной синхронизации остаются задачами приёмки. Синтетические проверки не измеряют экономию времени пользователей.

## Установка

Скачайте **DesktopPilot-0.2.111-windows-x64.zip**, распакуйте и запустите `desktop-pilot.exe`. Сверьте архив с **SHA256SUMS.txt**. Исходники — в **DesktopPilot-0.2.111-source.zip**. Исполняемый файл не подписан цифровой подписью.

## English

Desktop Pilot 0.2.111 removes newly created, **unjournaled** backup folders when a shortcut placement is interrupted before the durable prepared transaction. A changed or temporarily unreadable source can no longer accumulate those orphaned preparation backups across retries. Existing managed shortcuts and source files remain untouched. Once a transaction is journaled, its recovery backups and Undo behavior are preserved.

A native regression exercises the actual Windows shortcut and SQLite apply path, source mutation between scan and copy, unchanged ownership, no orphaned history or hidden staging, successful retry and Undo. Standard Windows Server 2022/2025 checks validate Rust tests, formatting, strict Clippy, build and native integration. This does not replace physical Windows 11/DPI and long-running cloud-sync acceptance, and does not claim measured time savings. See the [reproducible research](../research/2026-11-04-unjournaled-shortcut-preparation.md).
