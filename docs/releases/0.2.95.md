# Desktop Pilot 0.2.95 — уникальные ярлыки при вложенных системных папках

## Что исправлено

Если одна из системных папок Windows перенаправлена внутрь другой, Desktop Pilot мог просканировать вложенную папку повторно. Один и тот же ярлык дважды расходовал общий лимит обнаружения в 6 000 файлов. Из-за этого отдельные приложения из следующих папок, например меню «Пуск», могли не попасть в список.

Теперь общий лимит расходуется **только на уникальные пути исходных ярлыков**, независимо от числа пересекающихся системных папок. Существующие правила «Всегда» и «Никогда», порядок обхода, ограничения безопасности, файлы пользователя и история не меняются. Одинаковые цели запуска в двух разных файлах не объединяются на этом этапе: действующая проверка логической идентичности сохраняется.

## Проверки

[Описание воспроизведения](../research/2026-11-02-overlapping-known-folder-subroots.md): три реальных Windows-файла `.url`, первая папка с вложенным каталогом, второй корень, указывающий на этот каталог, и отдельное меню «Пуск». При синтетическом лимите три исходный алгоритм повторно учитывал ярлык из вложенного каталога и пропускал уникальный файл. После исправления находятся все три, результат совпадает со сканированием без пересекающихся корней, исходные байты не изменяются.

Наблюдение подтверждено анализом производственного обхода и регрессионной файловой фикстурой. Частота проблемы у реальных пользователей и выигрыш по времени не измерены. Полная проверка выпуска требует неизменённых Windows Server 2022/2025 Rust-тестов, форматирования, строгого Clippy, сборки, нативных интеграционных сценариев и проверок создания архива. Испытания реальных OneDrive/сетевых перенаправлений, Windows 11, Проводника и масштабирования 100–200% остаются отдельной задачей.

## Установка

Скачайте **DesktopPilot-0.2.95-windows-x64.zip**, распакуйте и запустите приложение. Контрольные суммы — **SHA256SUMS.txt**, исходники — **DesktopPilot-0.2.95-source.zip**. Исполняемый файл не имеет цифровой подписи.

## English

Desktop Pilot 0.2.95 prevents overlapping Windows Known Folder roots from charging the same source shortcut path more than once against the 6,000-file discovery budget. A descendant folder configured as a second root no longer hides unrelated Start Menu shortcuts at the limit. Deterministic directory priority, security checks, user files, manual Always/Never rules, history and Undo remain unchanged; no new telemetry or settings are introduced.

A production-path regression checks real Windows `.url` files under nested roots against a three-item boundary, verifies unchanged source bytes, and compares the result with nonoverlapping roots. This synthetic filesystem result is not evidence of real-user incidence or measured task-time improvement. The standard Windows CI, native checks and guarded release packaging remain mandatory. The Windows x64 binary is unsigned.
