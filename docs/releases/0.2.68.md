Desktop Pilot 0.2.68 — понятные причины сохранения ярлыков в ручном режиме.

## Что изменилось

В разделе **Приложения → Подробнее** для уже созданного быстрого ярлыка теперь отдельно объясняется, почему **новый** ярлык не предлагается и что произойдёт с **существующим**. Раньше при закреплении приложения на панели задач могло отображаться только «Уже закреплено на панели задач» — хотя выбранный пользователем ручной режим намеренно сохраняет прежний быстрый ярлык. Возникало впечатление, что обычное «Применить» удалит его.

Теперь для такого ярлыка прямо указано, что закрепление на панели задач само по себе **не удалит** существующую копию. Если исходный ярлык или цель долго недоступны, поясняется, что уже размещённая копия в ручном режиме **остаётся на месте**, но запуск может не сработать. Это устраняет противоречие между текстом интерфейса и фактическим размещением.

Ручное «Не добавлять» остаётся обязательным; в режиме наблюдения действуют прежние правила. Никаких изменений выбора, сохранённых файлов и настроек, истории, отмены, числа фоновых процессов, сети или сбора данных.

## Проверка

Регрессионные сценарии выполнены на настоящих `Settings`, локальной SQLite, обработке изолированных ярлыков `.url` и отрисовке окна Подробнее. Проверены уже размещённый закреплённый ярлык, десятидневная недоступность источника, переход в наблюдение, явное «Не добавлять», неизменность байтов исходника. Тест до исправления воспроизвёл несоответствующее сообщение; после исправления сценарии и штатные тесты прошли на Windows Server 2022/2025. Это не измерение экономии времени людей. Физическая Windows 11 при увеличенном масштабе интерфейса и настоящем отключении сетевых каталогов остаётся отдельно непроверенной.

Скачайте **DesktopPilot-0.2.68-windows-x64.zip**, распакуйте архив и запустите `desktop-pilot.exe`. Контрольные суммы — в **SHA256SUMS.txt**. Исполняемый файл не подписан цифровой подписью.

## English

Desktop Pilot 0.2.68 clarifies the difference between a shortcut being **ineligible for new placement** and an **existing managed shortcut remaining in place** in Manual mode. In Apps → Details, an already managed app pinned to the Windows taskbar now explains that the pin alone will not remove its shortcut. A long-unavailable original explains that the existing copy stays in place, although launching may fail.

Explicit Never and Observe/Adaptive behavior are unchanged. Selection, owned files, Undo, history and local settings are unaffected. The source-level mismatch was reproduced before the fix using the actual Settings, SQLite, Windows Internet Shortcut parser and egui Details rendering. Corrected tests passed the Windows 2022/2025 CI suite, but physical Windows 11 / network-disconnection usability tests remain outstanding. The Windows x64 executable is unsigned.
