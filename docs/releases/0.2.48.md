Desktop Pilot 0.2.48 согласует сохранение настроек с командой «Отключить», чтобы выбор пользователя не отменялся из-за одновременно работающих окон.

## Что исправлено

Когда одна копия настроек сохраняла изменения и собиралась восстановить фоновую работу, а другая в этот момент отключала Desktop Pilot, прежняя реализация могла принять решение о перезапуске до отключения, но выполнить его после. В результате явно выполненная команда «Отключить» рисковала оказаться отменённой более ранним сохранением.

Теперь сохранение, решение о восстановлении работы и сама попытка запуска выполняются под той же блокировкой профиля, что и отключение. Если отключение произошло после сохранения, оно остаётся последним действием. Если сохранение последовало за отключением, учитывается актуальная конфигурация; простая правка другой настройки не включает наблюдение.

Никаких новых служб, зависимостей, скрытого сбора данных или изменений базы. Исходные ярлыки, история, ручные правила, расположение и отмена действий сохраняются.

Для проверки добавлен воспроизводимый сценарий с реальными Windows mutex, асинхронным сохранением Settings и SQLite. Он останавливает сохранение на границе решения о запуске и проверяет, что одновременно выполняемое отключение не может обогнать сохранение. Это проверка порядка операций, а не измеренная экономия времени пользователя.

Скачайте `DesktopPilot-0.2.48-windows-x64.zip`; контрольные суммы находятся в `SHA256SUMS.txt`. Исполняемый файл Windows x64 не имеет цифровой подписи.

## English

Desktop Pilot 0.2.48 serializes Settings saves, optional background resume and explicit Turn off. Previously a save could decide to restart tracking, let another Settings window finish disabling the profile, then perform the delayed restart. The save and its conditional restart now share the same per-profile startup lock as Turn off. A later disable remains authoritative; an unrelated settings edit does not silently resume a disabled profile.

The regression uses the production asynchronous Settings save, SQLite and the real Windows named mutex with a deterministic checkpoint at the save/restart boundary. Original shortcuts, manual preferences, desktop positions, usage history and Undo are retained. No new dependencies, data collection or services. The Windows x64 executable remains unsigned.
