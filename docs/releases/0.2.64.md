Desktop Pilot 0.2.64 восстанавливает ручное управление после неожиданной остановки фонового процесса.

## Что изменилось

Если фоновой процесс завершился во время обновления каталога, применения правила или другой команды, незавершённая запись в базе раньше могла надолго заблокировать изменения настроек. Даже после остановки процесса окно иногда продолжало показывать индикатор выполняющейся команды.

Теперь отсутствие фонового процесса не мешает сохранять независимые настройки, даже если само открытое окно ещё помнит незавершённую команду. На главной странице можно явно пометить оставшиеся команды как прерванные. Перед этим программа проверяет блокировки запуска и работу нового фонового процесса, чтобы не отменить выполняющуюся команду по устаревшему состоянию. Ярлыки и их исходные файлы, ручные правила, история и возможность отмены размещения остаются нетронутыми.

Регрессионные сценарии выполняются на реальном пути Settings/SQLite с изолированными ярлыками, включая остановку фонового процесса, сохранение настройки, очистку прерванной команды и одновременный перезапуск. Это не измерение реальной экономии времени пользователя.

Скачайте **DesktopPilot-0.2.64-windows-x64.zip**, распакуйте и запустите `desktop-pilot.exe`. Проверочные суммы опубликованы в **SHA256SUMS.txt**. Исполняемый файл не подписан цифровой подписью.

## English

Desktop Pilot 0.2.64 restores manual control after a background-worker interruption. Pending or running commands abandoned by a stopped worker no longer freeze unrelated Settings edits, including actions still tracked by the same open Settings window. Home provides explicit interrupted-command cleanup. The cleanup locks out concurrent startup and refuses to cancel commands belonging to a newly resumed worker. Existing shortcut files, manual rules, history, and Undo are preserved. Regression coverage exercises actual Settings/SQLite and isolated shortcut paths; no telemetry, new service or dependency has been added. The Windows x64 executable is unsigned.
