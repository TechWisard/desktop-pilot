# Explain empty desktop organizer reviews — 2026-11-10

## Observed production behavior
The completed analyzer can return `items=[]` for two distinct reasons: an empty Desktop (`skipped=[]`) or every discovered object being protected, manually kept, or not eligible (`skipped` nonempty). In both states the original review showed a 0/0 selection bar, disabled bulk buttons, a checkbox instruction, and 0–0 / 0 pagination; excluded details were initially collapsed. In the latter case, people could reasonably mistake an intentional protection result for a broken or unfinished scan. This is directly verified from production `organize::analyze` and `Settings::organization_dialog`, **not** an independently reported Desktop Pilot user incident.

Existing research on predictable adaptive interfaces: Gajos et al., CHI 2008, https://www.eecs.harvard.edu/~kgajos/papers/2008/gajos08predictability.shtml . Design-system guidance recommends differentiating genuinely empty data from completed user actions, explaining the reason and one next step: https://atlassian.design/content/designing-messages/empty-state/ and https://www.sap.com/design-system/fiori-design-web/v1-154/foundations/best-practices/global-patterns/designing-for-empty-states . These references motivate presentation, not claims of measured time savings.

## Change
Show a single bilingual explanation after a completed empty analysis: add items and Analyze again when the Desktop was empty, or inspect the displayed reasons when all discovered objects stayed. Open the excluded-items disclosure by default only in the empty-proposal state, with a distinct egui persistence ID so an earlier manually closed disclosure from a populated review cannot hide first-time reasons. Once opened, the person may collapse it as before. Suppress inapplicable 0/0 selection controls, checkbox instructions, 0/0 page counter, and filtered bulk controls when there are no matching proposed items. Do not add controls or expand the entire list (existing 40-item paging remains). Existing nonempty reviews, search behavior, manual choices, policies and Apply/Undo logic remain unchanged.

## Reproducible acceptance
`empty_organizer_explains_saved_exclusions_and_a_truly_empty_desktop` uses a real disposable Windows Desktop with two parsed `.url` files, SQLite Store, genuine Analyze, explicit Keep-only application, fresh Analyze, then an empty Desktop and fresh Analyze. It inspects egui paint output in Russian and English at 100% and 200%, asserts visible saved exclusion reasons without another click, distinguishes empty states, hides inert actions, and verifies unchanged shortcut bytes, catalog, saved manual choices, disabled background state and absence of Undo journal. This is an interface correctness test, not a human-speed benchmark.

Run the exact proposed head on Windows 2022, 2025 and Windows 11 ARM including strict fmt, locked Rust tests, Clippy, native integration, Explorer, Cloud Files and interface review before merging. Do not publish 0.3.0: physical multi-monitor/DPI, active OneDrive account, interactive keyboard/accessibility and power-loss recovery acceptance are still required. Stable `main` and its latest released version remain unchanged.
