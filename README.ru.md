# Desktop Pilot

**Нужные ярлыки рядом. Порядок на рабочем столе — под вашим контролем.**

[Скачать для Windows](https://github.com/TechWisard/desktop-pilot/releases/latest) · [English](README.md) · [Руководство](docs/guide.ru.md) · [Приватность](docs/privacy.ru.md)

![Проверки Windows](https://github.com/TechWisard/desktop-pilot/actions/workflows/checks.yml/badge.svg)

Desktop Pilot — локальный органайзер рабочего стола и менеджер ярлыков Windows. Программа решает две отдельные задачи: поддерживает небольшую стабильную группу **копий ярлыков быстрого доступа** и **упорядочивает существующие объекты только по вашей команде**. Автоматическая адаптация не означает автоматическую уборку ваших файлов.

## Начало работы

1. Скачайте `DesktopPilot-*-windows-x64.zip` со [страницы последнего выпуска](https://github.com/TechWisard/desktop-pilot/releases/latest), сравните SHA-256 с файлом `SHA256SUMS.txt` и распакуйте архив.
2. Запустите `desktop-pilot.exe`. Выберите русский или английский язык и пройдите настройку. Автоматическая адаптация, наблюдение с ручным применением и полностью ручное управление — разные режимы.
3. Для упорядочивания существующих ярлыков откройте **«Использование → Навести порядок»**, проверьте предложенные группы, оставьте нужные объекты на месте и примените план.

Для обновления установленной программы откройте исполняемый файл из нового архива. Локальный профиль, правила и история сохраняются. EXE не имеет цифровой подписи; перед запуском проверяйте источник и контрольную сумму.

**Ветка разработки:** функция «Навести порядок», описанная ниже, ещё не включена в опубликованную версию 0.2.128. В этой ветке продолжается её приёмка.

## Исправления поиска из стабильной версии сохранены в этой ветке

## Улучшения версии 0.2.128

**Временная недоступность одного ярлыка больше не заставляет программу ошибочно приписывать использование другому профилю запуска.** Когда несколько сохранённых вариантов запуска имеют один идентификатор приложения Windows, Desktop Pilot учитывает и временно отсутствующие варианты. Если невозможно определить, какой именно профиль использовался, программа не начисляет активность наугад и не завышает его приоритет в автоматических рекомендациях. Для однозначного доступного ярлыка наблюдение работает как прежде. Ручные правила **«Всегда» / «Не добавлять»**, файлы, история, настройки и позиции значков сохраняются. [Проверка на Windows-ярлыках и SQLite](docs/research/2026-11-08-packaged-app-alias-attribution.md).

## Улучшения версии 0.2.127

**Скопированный адрес корня сайта теперь находит сохранённый ярлык независимо от необязательной косой черты `/` перед параметрами или фрагментом.** Точный поиск по-прежнему различает HTTP/HTTPS, регистр параметров, исходные ярлыки и правила **«Всегда»** / **«Не добавлять»**; упоминания адреса в чужих заметках не дают ложных совпадений. Исправление унаследовано из [выпущенной стабильной версии](https://github.com/TechWisard/desktop-pilot/releases/tag/v0.2.127), проверено на [реальных ярлыках и SQLite](docs/research/2026-11-07-http-root-lookup.md). Функция «Навести порядок» всё ещё не выпущена.

## Улучшения версии 0.2.126

**Полные пути запуска теперь сохраняют правильный ярлык и его ручное правило, не смешивая похожие каталоги.** Папка с буквальным именем `%USERNAME%` — не обязательно папка с именем учётной записи. Раньше разные программы и их рабочие каталоги могли получить один идентификатор, а проверка доступности иногда смотрела на чужой файл. Теперь правила **«Всегда»** / **«Не добавлять»** остаются независимыми, а временное отсутствие и восстановление файла определяются по его настоящему пути. Сокращённые шаблоны запуска `%SystemRoot%` работают как прежде. Исходные ярлыки, история, позиции и пользовательские настройки не переписываются. [Регрессии файловой системы, SQLite и выбора ярлыков](docs/research/2026-11-07-absolute-target-identity.md).

Функция «Навести порядок» из [PR #211](https://github.com/TechWisard/desktop-pilot/pull/211) ещё проходит приёмку и **не входит** в этот выпуск.

## Улучшения версии 0.2.125

**При поиске по полному пути редкого средства Windows теперь находится именно нужный профиль запуска.** Для файлов .com, .vbs, .vbe, .js, .jse, .wsf, .wsh и .msc применяется точное сопоставление пути, как уже было сделано для .exe, .cmd и .bat. Чужие заметки и файлы резервных копий больше не подменяют нужное приложение в результатах, в том числе под фильтрами **«Всегда»** и **«Не добавлять»**. Поиск по обычным словам остаётся широким. Поиск ничего не запускает и не изменяет файлы, настройки, историю или расположение значков. [Регрессионная проверка реального каталога и SQLite](docs/research/2026-11-07-windows-command-target-lookup.md).

Отдельная функция **«Навести порядок»** ещё проходит приёмку в [PR #211](https://github.com/TechWisard/desktop-pilot/pull/211) и **не входит** в этот выпуск.

## Улучшения версии 0.2.124

**Полный путь к файлу запуска `.cmd` или `.bat` теперь находит именно нужный ярлык и его сохранённое правило.** Раньше такой путь обрабатывался как обычный текст: в результатах могли появиться чужой ярлык с упоминанием этого пути в заметке или файл с более длинным именем. Теперь поиск по конкретному файлу различает профили и фильтры **«Всегда»** / **«Не добавлять»**, а поиск по словам и папкам остаётся широким. Ярлыки, история использования, настройки запуска и позиции на рабочем столе не меняются. [Воспроизводимый сценарий с Windows и SQLite](docs/research/2026-11-07-copied-batch-targets.md).


## Улучшения версии 0.2.123

**Поиск по скопированному полному пути показывает нужный ярлык и его правило.** В разных папках могут находиться одноимённые ярлыки, в том числе в каталоге с буквальным именем `%USERNAME%` и в каталоге с настоящим именем пользователя Windows. В разделе «Приложения» полные пути к файлам больше не подвергаются повторной подстановке переменных: раньше из-за этого могли одновременно находиться два разных ярлыка вместо одного выбранного. Правила **«Всегда»** и **«Не добавлять»** остаются раздельными; сокращённый поиск по `%SystemRoot%` работает как прежде. Оригиналы, расположение, история и настройки не меняются. [Регрессия на настоящих ярлыках и SQLite](docs/research/2026-11-06-literal-copied-path-search.md).

## Навести порядок без потери контроля

Сначала программа показывает предварительный план, ничего не перемещая. По умолчанию группируются обычные ярлыки `.lnk` и `.url`, а не документы, проекты и папки. Обычные файлы включаются отдельной настройкой. Ради одного объекта новая папка не создаётся.

У каждого предложения есть флажок. Поиск и страницы помогают просмотреть большой рабочий стол; фильтр не снимает выбор со скрытых строк. **«Запомнить исключения»** позволяет оставить всё на месте и сохранить этот выбор без перемещений и фиктивной записи отмены. Если после просмотра файл изменился или был заменён, старый план отклоняется до начала операции.

Исходные файлы перемещаются внутри личного локального рабочего стола, а не копируются с последующим удалением. Чужие папки не присваиваются программе, совпадающие имена не перезаписываются. Управляемые быстрые ярлыки, ручные правила и известные зависимости файлов защищены. Облачные заполнители, специальные ссылки, исполняемые файлы, скрипты и папки проектов не перемещаются скрытно.

Для упорядочивания предусмотрены отдельная **отмена** и постоянный журнал восстановления. После прерывания работы откройте программу и завершите восстановление. Уже возвращённый вручную оригинал распознаётся, а выбранное вами новое положение его значка сохраняется. Если прежнее имя занято другим файлом, восстановление останавливается, не уничтожая ни один объект. [Подробное руководство](docs/guide.ru.md)

## Привычные ярлыки не должны прыгать

Адаптация учитывает подтверждённую работу в активном окне, повторные обращения и давность использования, а не простое появление процесса. По умолчанию выделяются четыре быстрых ярлыка; пересмотр выполняется раз в семь дней с одной обычной заменой за раз. Первоначальное обучение ожидает семь подтверждённых сеансов работы; для каждого нужно пять минут учитываемой активности. Параметры можно изменить.

Правила **«Всегда / Автоматически / Никогда»** важнее рейтинга. Предел замен **0** сохраняет существующие ярлыки, но позволяет заполнить свободные места. Перемещённый вручную быстрый ярлык закрепляется. Удалённый не возвращается автоматически; изменённый выходит из-под управления программы. Временная недоступность источника не означает немедленного удаления рабочей копии. Разные профили запуска не объединяются.

Автоматические изменения ждут реального бездействия, отсутствия удерживаемых клавиш и кнопок мыши, а также выхода из полноэкранного режима. Перед изменениями условия проверяются повторно. **«Навести порядок» никогда не запускается автоматически.**

## Крупный интерфейс и локальные данные

Русский и английский языки, сохранение масштаба текста от 100% до 200%, масштабирование с клавиатуры, крупные элементы управления, поиск и отдельные подробности приложения. Дополнительные настройки не перегружают основной экран. Открытие настроек не включает остановленную программу без вашего решения.

Нет учётной записи, телеметрии, облачной синхронизации и сетевой службы. Локально сохраняются пути приложений, суммарная статистика, настройки и данные отмены — не вводимый текст, коды клавиш, заголовки окон, содержимое документов или история браузера. **Не публикуйте базу профиля и папку отмены.** [Подробнее о приватности](docs/privacy.ru.md)

## Совместимость и проверки

Программа предназначена для Windows 10/11 x64 со стандартным рабочим столом Explorer. Приёмка упорядочивания включает реальные перенос и отмену в Explorer Windows 11, проверки Windows Server 2022/2025, принудительное завершение отдельного процесса с последующим восстановлением, а также снимки работающего русского и английского интерфейса при 100% и 200%, включая прокрутку.

Тестовая Windows 11 работает на ARM64 с эмуляцией x64; для снимков используется программный рендерер, установленный только рядом с тестовым EXE. Это не сертификация физических x64-видеокарт и многомониторных конфигураций. Тесты настоящей логики размещения охватывают занятые позиции, отрицательные координаты и смену геометрии, но не заменяют все аппаратные сочетания. Синхронизация с действующей учётной записью OneDrive и альтернативные оболочки не сертифицированы. Неподдерживаемые облачные и сетевые объекты пропускаются или отклоняются, а не переносятся незаметно.

Для управления позициями значков нужно отключить автоматическое упорядочивание Explorer. Смена конфигурации экранов останавливает небезопасное размещение. [Описание выпуска](docs/releases/0.3.0.md) · [История проверок](docs/verification.md)

## Сборка

Установите Rust **1.93.1** с инструментами MSVC и Visual Studio C++ Build Tools:

```powershell
pwsh -File scripts/build-release.ps1
```

Скрипт проверяет форматирование, тесты и строгий Clippy, затем создаёт `target/release/desktop-pilot.exe`. Программа использует Rust, egui/eframe, SQLite и Windows Shell API. Обязательные уведомления о зависимостях сохранены в репозитории и дистрибутиве.

Изолированные нативные проверки запускаются с новым пустым тестовым профилем:

```powershell
target/release/desktop-pilot.exe --self-test --home "$env:TEMP\test-desktop-pilot-unique" --out "$env:TEMP\desktop-pilot-test.json"
```

Этот тест не изменяет настоящий рабочий стол и автозапуск. Проверки живого Explorer и Cloud Files отдельно ограничены одноразовой тестовой средой.
